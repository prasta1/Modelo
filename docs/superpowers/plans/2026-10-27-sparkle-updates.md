# Sparkle In-App Updates Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Modelo notices new releases, shows their notes, and on **Install Update** downloads, replaces itself and relaunches, with every update EdDSA-verified.

**Architecture:**
- Sparkle 2 (SPM) with `SPUStandardUpdaterController` owned by `ModeloApp`, plus a **Check for Updates…** menu command.
- Each release attaches a single-item `appcast.xml`, generated by a script in `release.yml` and signed with `sign_update`.
- Modelo reads the feed through GitHub's `releases/latest/download/` redirect.

**Tech Stack:** Swift/SwiftUI, Sparkle 2.x, XcodeGen, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-27-homebrew-sparkle-design.md` (Part 2). Do the Homebrew tap plan first.

## Global Constraints

- Sparkle via SPM in `project.yml`, pinned with `exactVersion:` to the latest 2.x release at build time (≥ 2.7.0). `xcodeproj` and `Package.resolved` aren't committed, so `from:` would float.
- `project.yml` dependency comment must say why Sparkle is the third dependency (user chose Sparkle for in-app installs).
- `SUFeedURL` = `https://github.com/prasta1/Modelo/releases/latest/download/appcast.xml`
- `SUPublicEDKey` = public key from `generate_keys`. `SUEnableAutomaticChecks` **unset**, so Sparkle asks on the second launch. Interval: default (daily).
- Appcast fields:
  - `sparkle:version` = `CURRENT_PROJECT_VERSION`
  - `sparkle:shortVersionString` = `MARKETING_VERSION`
  - `sparkle:minimumSystemVersion` = `14.0`
- New secret `SPARKLE_ED_PRIVATE_KEY`, backed up in the user's password manager.
- No update installs without a click. The updater never starts under XCTest.
- Don't regress manual Developer ID export (`scripts/ExportOptions.plist`) or the `keychain-access-groups` / `com.apple.application-identifier` entitlements.

## Review Focus

1. **Build number not increased:** Sparkle silently offers nothing. The workflow must fail when `CURRENT_PROJECT_VERSION` ≤ the previous release's `sparkle:version` (Task 3, Step 2).
2. **First Sparkle release has no previous appcast:** the build-number check must pass when `releases/latest/download/appcast.xml` 404s (Task 3, Step 2).
3. **Tampered or wrongly-signed zip:** Sparkle must refuse it (Task 4, Step 3).
4. **Test runs start the updater:** the host app launched by `ModeloTests` must not check feeds or show the consent prompt (Task 1, Step 1).
5. **Update drops keychain entitlements:** the updated app must load saved API keys with no password prompt (Task 4, Step 2).

### Task 2: Appcast generator script

**Files:**
- Create: `scripts/make-appcast.sh`

**Interfaces:**
- Produces: `scripts/make-appcast.sh <short-version> <build> <zip-url> <sign-update-output> <notes-html-file>`. It writes a one-item appcast to stdout.
  - `<sign-update-output>` is `sign_update`'s literal `sparkle:edSignature="…" length="…"` string, inserted verbatim into `<enclosure>`.
  - Notes go in `<description><![CDATA[…]]></description>`.
  - `sparkle:minimumSystemVersion` is `14.0`.

- [ ] **Step 1: Write the check**, a snippet in the task notes that:
  - runs the script with `0.4.0 5 https://example/Modelo-v0.4.0.zip 'sparkle:edSignature="SIG" length="123"' notes.html` (notes containing `<h2>Hi & bye</h2>`);
  - pipes the output to `xmllint --noout -`, which must exit 0;
  - asserts the output contains `<sparkle:version>5</sparkle:version>`, `<sparkle:shortVersionString>0.4.0</sparkle:shortVersionString>`, `sparkle:edSignature="SIG"`, and the notes inside CDATA.

- [ ] **Step 2: Run the check** → fails (script missing).
- [ ] **Step 3: Implement** with a heredoc. Use the Sparkle 2 namespace `xmlns:sparkle="http://www.andymatuschak.org/xml-namespaces/sparkle"`.
- [ ] **Step 4: Run the check** → passes.
- [ ] **Step 5: Commit.**

### Task 3: Release workflow signs, checks the build number, and attaches the appcast

**Files:**
- Modify: `.github/workflows/release.yml`
- Modify: `AGENTS.md` (Releasing: `SPARKLE_ED_PRIVATE_KEY` secret row; the rule that `CURRENT_PROJECT_VERSION` must increase every release)

**Interfaces:**
- Consumes: `scripts/make-appcast.sh` (Task 2); Sparkle's `sign_update` from the SPM artifact.

- [ ] **Step 1: Pin package checkout location.** Add `-clonedSourcePackagesDirPath build-release/spm` to the archive command, so `sign_update` is at `build-release/spm/artifacts/sparkle/Sparkle/bin/sign_update`.

- [ ] **Step 2: Add a build-number guard step** before `Archive + export`:
  - `curl -fsL https://github.com/prasta1/Modelo/releases/latest/download/appcast.xml`. On failure (no previous appcast), echo a notice and pass.
  - Otherwise extract `<sparkle:version>` and fail with `::error::` unless `CURRENT_PROJECT_VERSION` from `project.yml` is strictly greater.
  - Dry-run it locally: against the absent feed (today) → passes. Against a temp file containing `<sparkle:version>3</sparkle:version>` with the current build `3` → fails.

- [ ] **Step 3: Restructure `Publish release`.** After the notes and SHA-256 line are built:
  - write `SPARKLE_ED_PRIVATE_KEY` to `$RUNNER_TEMP/sparkle.key`;
  - run `SIG=$(sign_update --ed-key-file "$RUNNER_TEMP/sparkle.key" "$ZIP")`;
  - render the notes to HTML with `gh api markdown -f text="$(cat notes.md)" -f mode=gfm -f context="$GITHUB_REPOSITORY"`;
  - run `make-appcast.sh` with the zip URL from the Homebrew plan's URL pattern, writing `appcast.xml`;
  - `gh release create … "$ZIP" appcast.xml --notes-file …`.
  - The bump-cask step stays after this.

- [ ] **Step 4: Verify.**
  - The YAML parses. The step order is guard → archive → notarize → publish → bump-cask → cleanup.
  - Dry-run the publish script locally the same way as the SHA-256 change: swap `gh release create` for `xmllint --noout appcast.xml && cat appcast.xml`, with a throwaway key: run `generate_keys --account modelo-dryrun`, export it with `generate_keys --account modelo-dryrun -x <scratch>/dry.key`, and delete that keychain item afterwards. The signature is only checked for format here.

- [ ] **Step 5: Update AGENTS.md, commit, and open the PR** with `--repo prasta1/Modelo`.

### Task 4: End-to-end proof, then ship

- [ ] **Step 1: Local update test (Debug).**
  - Build two Debug apps into the scratchpad with `CURRENT_PROJECT_VERSION=1000` and `1001`.
  - Zip the 1001 app with `ditto -c -k --keepParent`. Sign it with `sign_update <zip>` and no key-file flag: both builds carry the real `SUPublicEDKey`, and `generate_keys` left the private key in the login keychain.
  - Build the appcast with `make-appcast.sh` and serve the folder with `python3 -m http.server 8000`.
  - `defaults write com.peregrine.modelo ModeloDebugFeedURL http://localhost:8000/appcast.xml`, then launch 1000 and choose **Check for Updates…**.
  - Expected: the update window shows the notes. **Install Update** relaunches into 1001 (About shows build 1001).

- [ ] **Step 2: Keychain survives.** After Step 1, a saved API key loads with no password prompt.

- [ ] **Step 3: Tamper test.** Flip one byte in the served zip and repeat → Sparkle refuses ("improperly signed"). Then `defaults delete com.peregrine.modelo ModeloDebugFeedURL`.

- [ ] **Step 4: Ship.**
  - Merge, bump `MARKETING_VERSION` and `CURRENT_PROJECT_VERSION` (+1), and push the tag.
  - Confirm the release has `appcast.xml`, and that `curl -sL …/releases/latest/download/appcast.xml | xmllint --noout -` passes.
  - Add to the release notes: v0.3.1 users must download this version once by hand.

- [ ] **Step 5: Homebrew `auto_updates`.** In `prasta1/homebrew-modelo`, add `auto_updates true` below `version` in `Casks/modelo.rb`, then run `brew style` and `brew audit`, commit and push.
  - This is a one-time hand edit; the bump script preserves it.
  - The spec suggested doing it through the workflow, but a single edit is simpler, so this is a deviation.
